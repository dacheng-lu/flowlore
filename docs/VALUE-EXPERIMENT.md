# Value experiment: reusable record

Status: template for planning and documenting an experiment, not verified customer evidence.
Keep task records in an appropriately private location; publish only consented, anonymized
summaries. Never include credentials or identify interviewees in a public repository.

## Before the experiment

- Purpose: commercial / internal efficiency / open source / learning / other
- User and situation; current alternative and baseline:
- Hypothesis and specific outcome; what would disprove it:
- Audience, offer and revision (include price and buyer if applicable):
- Recruitment channel and selection method:
- Method, window, target sample, budget and costs to measure (including human work):
- Continue / adjust / stop thresholds, set before collecting results:

## Observations

| Date | Source and evidence locator | Observed action or result | Sample / denominator | Scope and limitations | Kind |
| --- | --- | --- | --- | --- | --- |
| | | | | | synthetic / self-reported / directly observed / unknown |

Include negative and missing outcomes. Preserve source date, version and observation date.
A paid pilot, renewal and successful use are different observations; enthusiasm or a signup is
not payment. Revenue, recurring revenue and profit are distinct; record costs separately.

## Decision

- Experiment status: planned / in progress / completed / blocked
- Hypothesis: supported / not supported / inconclusive (with explanation, not a universal score)
- Costs, alternatives, counterexamples, uncertainty and who decided:
- Next bounded action or reason to stop:
- What changed in the audience, price or promise since the observation:

## Independent evidence dimensions

Technical reproducibility, actual use, user outcome and commercial evidence are independent.
The catalog's `draft`, `field-tested`, and `verified` statuses refer to technical evidence, not
value or sales. A verified technical recipe may lack users, and a useful internal workflow need
not make money. Do not mark a recipe verified based on this record alone. See [catalog](CATALOG.md).

For a practical offline runner example see [Makeextreme value validation](https://github.com/dacheng-lu/makeextreme/tree/main/examples/value_validation);
for decisions across sessions see [Longhaul](https://github.com/dacheng-lu/longhaul/blob/main/references/value-validation.md).
These links do not imply an automatic integration.
